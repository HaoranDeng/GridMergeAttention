# C8 exponential reuse diagnostic, 2026-09-18

Five subsequent optimizations also failed to beat r2. The normalized-cache
variant v9 passes the three-capture numerical screen, avoids both a repeated
per-key exp and a new per-key log, and has zero local allocation. Its complete
call is 0.49% slower (within timing noise) and its isolated H5 merge is 2.62%
slower in every paired measurement. Default C8 remains r2.

The initial in-place candidate overwrites each seed row's logits with its FP32
softmax probabilities after the row's range check. It compiles without local
memory and passes the final-output error screen on three real captures.
The subsequent scai6 measurement found a **1.41% slower complete call** and a
**4.32% slower H5 merge** than its same-run r2 control. Default C8 remains r2;
the earlier C8 remains `slow_reference`.

The first scai7 run skipped in-place timing because its runner incorrectly
gated on intermediate closeness. The corrected scai7 launch found no clean
H200. The user then explicitly directed the timing run to scai6.

## Algebra and storage

For seed row i, let E_ij = exp(S_ij - m_i), Z_i = sum_j E_ij,
P_ij = E_ij / Z_i, and M_ij indicate ownership selected by argmax_i P_ij.
Then merge weights are

    W_ij = M_ij P_ij / sum_j M_ij P_ij
         = M_ij E_ij / sum_j M_ij E_ij.

No second exponential is required to form W. Original logits need not remain
live after softmax. The in-place variant retains logits only until the current
row's direct-exp range check and possible max-subtracted fallback finish.

The merge also computes entropy bias, not just weights. With
A_i = sum_j M_ij P_ij, its existing bias convention is

    bias_i = sum_j W_ij log(P_ij) - log(A_i) = sum_j W_ij log(W_ij).

Thus the in-place implementation computes log(P) for selected probabilities.
It trades the second exp for log and changes register lifetimes; speedup cannot
be inferred from the removal of exp alone. Empty clusters retain positive
infinity bias. Zero probabilities contribute zero to the entropy moment.

Raw-E reuse variants retain log(P) and add log(Z) to the bias expression to
cancel the row normalizer. A float64 CPU identity check covering random,
tied, empty-cluster and extreme-logit examples had maximum bias error
8.88e-16. This checks the algebra, not CUDA rounding behavior.

not the user's acceptance requirement.

## Further optimization attempts on scai6

After the user requested optimization, five new variants were built and
measured on the same exclusively idle GPU 5. Both additional runs completed
with valid timings and no monitoring errors. They use the same prespecified
error thresholds, captured tensors and paired measurement protocol.

- **v5:** scale logits in place before exp and the range check. This removes
  the need to retain unscaled logits across the fallback, making raw-exp reuse
  fit at four-CTA residency without spilling. The rare fallback now uses a
  rounded multiply and subtraction instead of the original fused operation.
- **v6:** cache one half of the exponentials in each warp's existing TMA
  staging slice. Each slice uses 2,560 of its existing 4,096 bytes, with a
  per-warp asynchronous-store read wait before reuse. No new shared allocation
  or cross-warp scratch dependency is introduced.
- **v7:** combine v5 and v6.
- **v8:** use v5's scaling, but retain the original array-based reductions and
  masked-weight layout instead of signed-probability streaming.
- **v9:** use v8's layout and convert cached E to P using the first row sum.
  Reuse log(P) from the retained score representation for the entropy moment;
  neither a second per-key exp nor a new per-key log is required. This is the
  same probability-renormalization identity, with different FP32 rounding.

v5-v8 have a layer-00 max-error/peak ratio of 2.00730%, just above the fixed
2% screen, so that capture was not timed. This is a screening outcome, not a
claim that their mathematical operator is different. v9 passes all three
captures against both references: maximum relative L2 is 1.59823e-4 versus r2
and 2.59050e-4 versus `slow_reference`; maximum error/peak is 1.64234%.

All new variants have 128 registers, zero local bytes and four CTAs per SM.
Each one's isolated merge is slower in every tested pair (16/16 for v5-v8,
24/24 for v9). The complete-call differences for v5, v8 and v9 have approximate
pooled paired intervals crossing zero; do not present those small mean
differences as established complete-call regressions or speedups.

Static SASS inspection helps constrain the explanation but is not a latency
profile. The full-H40 merge function has 1,608 static instructions in r2,
1,792 in the initial in-place v4, 1,632 in v8 and 1,664 in v9. Static EX2 sites
fall from 100 to 80 (these counts include the stable fallback), while v9
retains two LG2 sites instead of v4's 21. V9 also increases FMUL sites from 92
to 136 and FSEL sites from 47 to 69 relative to r2. Thus removing repeated exp
does not remove all of the data-selection and normalization cost. These
counts alone do not establish which instruction class dominates runtime.

No variant was promoted. All comparisons are kernel diagnostics; no video
generation or video-quality evaluation was started.
