The in-place candidate overwrites each seed row's logits with its FP32
softmax probabilities after the row's range check. It compiles without local
memory and passes the final-output error screen on three real captures.
Its runtime is **unmeasured**: the original runner incorrectly gated timing on
intermediate closeness, and the corrected launch found no clean H200. Default
C8 remains r2; the earlier C8 remains `slow_reference`.

## Algebra and storage

For seed row i, let E_ij = exp(S_ij - m_i), Z_i = sum_j E_ij,
P_ij = E_ij / Z_i, and M_ij indicate ownership selected by argmax_i P_ij.
Then merge weights are

    W_ij = M_ij P_ij / sum_j M_ij P_ij
         = M_ij E_ij / sum_j M_ij E_ij.

No second exponential is required to form W. Original logits need not remain
live after softmax. The in-place variant retains logits only until the current
row's direct-exp range check and possible max-subtracted fallback finish.

The merge also computes entropy bias, not just weights. With
A_i = sum_j M_ij P_ij, its existing bias convention is

    bias_i = sum_j W_ij log(P_ij) - log(A_i) = sum_j W_ij log(W_ij).

Thus the in-place implementation computes log(P) for selected probabilities.
It trades the second exp for log and changes register lifetimes; speedup cannot
be inferred from the removal of exp alone. Empty clusters retain positive
infinity bias. Zero probabilities contribute zero to the entropy moment.

Raw-E reuse variants retain log(P) and add log(Z) to the bias expression to
cancel the row normalizer. A float64 CPU identity check covering random,
tied, empty-cluster and extreme-logit examples had maximum bias error
8.88e-16. This checks the algebra, not CUDA rounding behavior.

## Numerical observations

The engineering final-output screen uses relative L2 <= 1e-3 and
max-absolute-error / reference-absolute-maximum <= 0.02 against **both** r2 and
`slow_reference`, plus valid special-value semantics. These are experiment
screening thresholds, not a universal tolerance specified by the user.

| In-place v4 layer | Relative L2 vs r2 | Max error / r2 peak | Relative L2 vs slow reference |
| --- | ---: | ---: | ---: |
| 00 | 2.44028e-4 | 1.64234% | 1.98402e-4 |
| 19 | 8.71939e-5 | 0.61475% | 7.32527e-5 |
| 39 | 1.17952e-4 | 1.23057% | 8.68629e-5 |

Final outputs are finite and seed indices match. Probability-domain packed
comparison can choose different owners near ties than r2's log-domain packed
comparison. Individual clusters can consequently have larger intermediate
differences despite close final outputs. Bitwise or intermediate equality is
not the user's acceptance requirement.

The completed runner nevertheless gated timing on all intermediate-closeness
checks and skipped in-place v4. The current runner corrects this: it retains
the same final-output thresholds and checks intermediate validity, while
recording intermediate closeness as diagnostic. The completed result is
preserved unchanged as `result_v2.json`, with its exact runner archived as
`benchmark_v2_frozen.py`. Do not interpret its original `screen_passed: false`
as failure of the in-place final-output screen.

The lb3 variant's layer-00 max-error ratio was 2.00730%, slightly over the 2%
screen; it was not timed on that layer. Layers 19 and 39 passed.
