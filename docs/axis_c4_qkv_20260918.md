# Exact-C4 THW axis QKV screen, 2026-09-18

Quick diagnostic requested by the user. No video generation, training, model changes, or default promotion.

The leading follow-up is query T21 / key W80. Its case-mean relative L2 is 1.732%, versus 2.356% for query H45 / key W80 under the common current-line policy: 26.5% lower, winning 82/96 cases. Both retain 3,780 K/V slots per query. Query H45 / key T21 gives 3.225% error while retaining 14,400 slots, so it is not favored by this screen.

## Protocol

- Frozen real Wan2.1-14B-720p four-step dense-trajectory QKV, after RMSNorm and RoPE.
- Three canonical prompts, seed 0, four denoising steps, layers 0 and 33, heads 0/10/20/30.
- 96 QKV/head cases per method. Same 27 coordinates per case: T={0,10,20}, H={0,22,44}, W={0,40,79}; 2,592 query vectors per method.
- Every sampled query attends to all compressed key groups across the full 75,600-token volume.
- Exactly four merged slots per key line, zero KV and masked route for empty clusters, entropy bias, no singleton.
- Main six-way comparison: current-line anchor-Fisher seed selection, Uniform-16 key probes, three Gram-Schmidt pivots. C32/g45 geometry for H/W query lines; all 21 rows for T query lines.
- RF0 controls: select spatial query seeds from physical time zero, then merge using the current query line. RF0 is undefined for a temporal query line because it supplies only one in-line query.
- Original BF16 inputs; FP32 dot/reductions, FP64 Fisher/Gram-Schmidt, BF16 merge weights and merged KV, FP32 routing. This is a common mathematical reference, not bitwise reproduction of a production kernel.
- One clean scai7 H200 GPU1 at a time. Both monitored runs completed with no foreign GPU processes.

## Interpretation and limits

- Compare the two layer columns: the axis ranking is layer dependent. This screen cannot establish a universal winner across all 40 layers or a final video-quality winner.
- Equal C is not equal compute. Key T/H/W gives 19.05%/8.89%/5.00% retained slots. Query T produces 3,600 groups versus 1,680 for query H, increasing selection/merge work even when key W keeps the routed K/V count unchanged.
- These are structured sampled query coordinates, not a random estimate over all 75,600 queries. First/middle/last positions are intentionally represented; the frame weighting differs from the full sequence.
- Pooled energy-weighted errors and per-step/per-prompt means are preserved in summary.json. They weight heads differently and must not be mixed with the primary case-mean ranking.
- mean_attention_ms = unmeasured; speedup_vs_sdpa = unmeasured. The raw Python reference timings cover only 27 sampled queries per head and are not complete-call latency or a kernel-speed benchmark.
- PSNR, SSIM, LPIPS, and VBench are unmeasured because no videos were generated.
- Maximum relative difference between the recomputed FP32 dense target and saved BF16 dense output: 0.1955%.

Matched Flash SDPA mean attention: 330.485 ms. Each complete-call measurement includes selector, packing, merge and full compressed routing, excluding input loading, compilation, and model projections. Three warmed event-timed repeats per method per capture, interleaved forward/reverse order, 24 captures, one exclusive H200.

- T-query/W-key C4 versus c4_native: error ratio 0.7406; mean error reduction 25.94%; wins 81/96 matched head cases.
- T-query/W-key C4 versus c8_r2: error ratio 0.8967; mean error reduction 10.33%; wins 55/96 matched head cases.

C8 uses its shipped Hellinger/RF0 selection; C4 uses Fisher selection. Therefore the production comparison is not an isolated capacity-only ablation. The axis reference uses FP32 routing/output after BF16 merge weights/KV, while native C4/C8 return BF16 output and use their own numerical implementations. Small accuracy margins are provisional until the candidate has a matched native implementation. C8 is unchanged r2, with exactly eight slots and no singleton.
